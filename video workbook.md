# Software as Analogy: Audio-First Motion Canvas Playbook

Written from the Docker video project, October 2026. Give this document to any AI assistant before it touches the project.

## 1. How to use this document

This is a step-by-step runbook for producing a narrated explainer video with Motion Canvas, where the real narration audio controls the animation timing. Work through the phases in order. Each phase ends with a gate: stop, check the result yourself, and only then continue.

Rules for any AI assistant following this playbook:

1. Work one phase at a time and stop at every gate. Do not build the whole video in one go.
2. Label every claim VERIFIED (with evidence such as command output) or BELIEVED. Test before relying on anything.
3. Never create files by pasting multi-line code into a shell that will run it as commands. Use file tools, or PowerShell here-strings written to a file.
4. Do not create index.html. Do not hand-write vite.config.js or package.json. The official scaffolder generates them.
5. Never promise a video length. Report real durations from manifests and ffprobe.
6. Never claim a video has audio, or is in sync, until ffprobe and cue-frame checks support it.

## 2. The mistake this playbook prevents

The first Docker video was built animation-first. Scenes used hardcoded waitFor values, and the narration cue times were calculated by adding those waits up. The voice was recorded afterwards, so visual events drifted away from the spoken words. Matching total duration does not prove synchronization.

The fix is the order: script, then audio, then a measured timing manifest, then animation that waits on manifest timestamps, then verification. The audio file is the source of truth.

## 7. Phase 3: Script

Save the script as narration/script.txt, one spoken phrase per line, in this format:

```text
scene1|h01|It works on my machine.
scene1|h02|It is one of the oldest complaints in software.
```

Rules:

- One line is one idea, and becomes one WAV file and one timing segment. This gives phrase-level sync.
- Never put the pipe character inside the text.
- Spell symbols the way they should be spoken: docker P S, dash p, 8000 colon 5000. Whether Kokoro pronounces a spelling well is unverified until you listen.
- Review the facts before generating audio. Each line must be technically accurate. For example, containers share the host kernel, and no tool secures anything automatically.
- Approval gate: no audio is generated until the script is approved. Editing a line later means regenerating its WAV and re-timing its scene.

Length check: word counts do not give runtime. The Kubernetes script had 102 lines and the manifests added up to about 8 minutes 54 seconds, far above the intended five minutes. Decide the target length before animating, and trim lines first.

## 8. Phase 4: Generate narration audio

Kokoro is used through its Python API (not a command-line tool). The generator below reads the script, joins every chunk Kokoro returns for a line, and writes 24 kHz 16-bit mono WAVs. It caches by voice, speed and text, so an edited line regenerates only its own WAV. Save as tools/gen_audio.py:

```python
import argparse
from pathlib import Path

import numpy as np
import soundfile as sf
from kokoro import KPipeline

ap = argparse.ArgumentParser()
ap.add_argument('--voice', default='af_heart')
ap.add_argument('--speed', type=float, default=1.0)
ap.add_argument('--only', default='')
args = ap.parse_args()

root = Path(__file__).resolve().parent.parent
lines = (root / 'narration' / 'script.txt').read_text(encoding='utf-8').splitlines()
pipeline = KPipeline(lang_code='a')

done = skipped = 0
failed = []
for line in lines:
    if not line.strip():
        continue
    parts = line.split('|', 2)
    if len(parts) != 3:
        print('Bad line:', line)
        continue
    scene, sid, text = (p.strip() for p in parts)
    if args.only and scene != args.only:
        continue
    d = root / 'narration' / scene
    d.mkdir(parents=True, exist_ok=True)
    wav, keyf = d / (sid + '.wav'), d / (sid + '.key')
    key = args.voice + '|' + str(args.speed) + '|' + text
    if wav.exists() and keyf.exists() and keyf.read_text(encoding='utf-8') == key:
        skipped += 1
        continue
    try:
        chunks = []
        for _, _, audio in pipeline(text, voice=args.voice, speed=args.speed):
            chunks.append(audio.numpy() if hasattr(audio, 'numpy') else np.asarray(audio))
        if not chunks:
            raise RuntimeError('no audio produced')
        sf.write(str(wav), np.concatenate(chunks), 24000, subtype='PCM_16')
        keyf.write_text(key, encoding='utf-8')
        done += 1
        print('Wrote', scene + '/' + sid + '.wav')
    except Exception as e:
        failed.append(scene + '/' + sid)
        print('FAILED', scene + '/' + sid, e)

print('Generated:', done, 'Skipped:', skipped, 'Failed:', len(failed))
raise SystemExit(1 if failed else 0)
```

Run one scene first, then everything:

```powershell
python tools/gen_audio.py --voice af_heart --only scene1
python tools/gen_audio.py --voice af_heart
```

The torch warnings printed on startup are harmless. A different AI version of this script wrote the WAV inside the chunk loop, which overwrites earlier chunks. The version above concatenates them.

Gate: a human listens to the clips and flags clipped ends, odd pauses and mispronunciations before any animation is built.

## 9. Phase 5: Timing manifest

tools/build-manifest.mjs (Node, no extra dependencies) reads each scene's WAVs in script order and writes two things per scene: src/audio/sceneN.wav and src/timing/sceneN.json.

Requirements:

- Measure duration from the WAV sample count. Never estimate.
- Join lines with explicit silence: lead 0.5 s, gap 0.4 s, tail 1.0 s (configurable).
- Manifest fields: audio_file, sample_rate, audio_duration_seconds, audio_sha256, and segments with id, start, end and text.
- Hash the complete written WAV file including its header. Hashing only the raw samples caused a false hash mismatch in verification.
- Fail loudly if a line's WAV is missing. A version that skipped missing files silently would shift every later timestamp.
- Proposed, not yet tested: pad each scene's tail so its length is a whole number of video frames (1/30 s at 30 fps), so scene audio and scene video cannot drift apart across many scenes.

tools/verify.mjs must check: the manifest hash matches the current WAV, segments are ordered and non-overlapping, the scene covers the narration, and (after rendering) the MP4 has an audio stream whose duration matches within 0.1 s. Status: a basic hash check was run and passed for all eight Kubernetes scenes. The ffprobe checks are not yet written or tested.

Believed timing helper (src/lib/timing.js), to be tested:

```js
import {useThread, waitFor} from '@motion-canvas/core';

// Wait until the scene clock reaches t seconds.
export function* waitUntilTime(t) {
  const now = useThread().time();
  if (t > now) {
    yield* waitFor(t - now);
  }
}
```

Scene rules:

- Every visual event starts at its segment start, or at a documented offset inside the phrase. Comment each event with its segment id.
- Multi-step visuals spread across the segment duration. Keep natural pauses.
- A scene ends at its manifest audio_duration_seconds, so speech is never cut off.
- Build one scene as a proof first, with its own test project file, and verify it before building the rest.
- Keep visuals light: flat colors, thin strokes, no heavy blur or shadows.
- Placeholder scenes that only change text do not meet the style brief. Reuse the Docker scenes' layouts as the visual reference.

## 11. Phase 7: Register scenes

A scene file does nothing until src/project.js imports it. Forgetting this made scenes 4 to 8 not appear in the Docker project.

Rules:

- Import with the ?scene suffix: import scene1 from './scenes/scene1?scene';
- The project file is src/project.js for this scaffold. A different AI wrote src/project.ts without the ?scene suffix, which is wrong.
- Generate project.js from the scene files with a small Node script that sorts by scene number, and run it after every new scene. Do not hand-edit it each time.
- Back up project.js before overwriting it.

Gate: the timeline in the editor lists every scene.

## 12. Phase 8: Get audio into the video

Plan A (UNVERIFIED): set audio in makeProject so the editor plays it and the FFmpeg exporter embeds it. Confirm by running ffprobe on the rendered MP4 and looking for an audio stream.

Plan B (deterministic fallback, UNVERIFIED on this machine): render video only, then mux the original audio without re-timing it. The WAV must be re-encoded to AAC to fit in an MP4. Never change audio speed or add a start offset.

```powershell
& './node_modules/@ffmpeg-installer/win32-x64/ffmpeg.exe' -i output/project.mp4 -i src/audio/full.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k output/final.mp4
```

src/audio/full.wav is the scene WAVs concatenated in order, same sample rate and format. This works only if each scene video has the same length as its audio, which is why the frame-aligned padding in Phase 5 matters.

## 13. Phase 9: Verify

A successful render proves nothing about sync. Check the exported file:

```powershell
& './node_modules/@ffprobe-installer/win32-x64/ffprobe.exe' -v error -show_entries stream=codec_type,duration:format=duration -of json output/final.mp4
```

- A video stream and an audio stream are both present.
- Audio and video durations match within 0.1 s.
- Scene boundaries fall at the expected times (sum of scene durations).
- Cue frames: extract a frame at a segment start and look at it.

```powershell
& './node_modules/@ffmpeg-installer/win32-x64/ffmpeg.exe' -ss 12.5 -i output/final.mp4 -frames:v 1 cue.png
```

- Finally watch the video with sound, listening for visuals that arrive early or late.

## 15. Revising one line

1. Edit the line in narration/script.txt.
2. Run python tools/gen_audio.py --voice af_heart. Only that WAV regenerates.
3. Run the manifest builder. The scene's hash changes.
4. Verification must fail until the manifest is rebuilt and the scene is rechecked.
5. Re-check the affected visual cues, then re-render only that scene's range and rebuild the final file.

Never silently regenerate audio after animation timing has been set.
